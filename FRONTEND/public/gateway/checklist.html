Quack Gateway — Checklist de Instalação

Guia de campo para instalar o Gateway local na loja do cliente

Pré-requisito único: o Gateway é self-contained — a máquina do cliente não precisa de .NET, SQL Server, Node nem Docker. Você leva tudo pronto no pendrive.

A. No seu PC (antes da visita) precisa do .NET SDK 8

  1. Abra o PowerShell na pasta GATEWAY e gere o build: 
    dotnet publish src/HorusGateway -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o publish-service
  2. Copie para o pendrive a pasta GATEWAY com: publish-service\, install-service.ps1, uninstall-service.ps1, setup-https.ps1 e este checklist.
  3. Anote o CompanyId real da empresa na Cloud (tem que bater — isolamento por empresa).

B. Na máquina do cliente (onde o Gateway vai ficar — ex.: PC do caixa)

  1. Copie a pasta do pendrive para C:\QuackGateway.
  2. IP fixo: rode ipconfig, anote o IP e reserve no roteador (DHCP reservation). Ex.: 192.168.0.10.
  3. Abra o PowerShell como Administrador e escolha UM cenário abaixo.

Cenário 1 — Sistema em HTTP / app desktop

O mais simples. Porta 5080.

cd C:\QuackGateway
.\install-service.ps1 -SkipPublish `
  -CompanyId <EMPRESA> -StoreId loja-01 -Port 5080

Teste: http://localhost:5080/ abre o painel.

Cenário 2 — Sistema em HTTPS

O navegador exige HTTPS no Gateway. Porta 5443.

cd C:\QuackGateway
.\setup-https.ps1 -IpAddress 192.168.0.10 `
  -PfxPassword "umaSenhaForte"

$env:GATEWAY_HTTPS_CERT="C:\QuackGateway\certs\quack-gateway.pfx"
$env:GATEWAY_HTTPS_CERT_PASSWORD="umaSenhaForte"
$env:GATEWAY_PORT=5443
.\install-service.ps1 -SkipPublish -CompanyId <EMPRESA> -StoreId loja-01

Em CADA terminal: instale o certs\quack-gateway.cer em “Autoridades de Certificação Raiz Confiáveis”.

C. Configurar e validar

  1. No painel do Gateway (http(s)://<IP>:porta/), pré-autorize os terminais informando o IP de cada um (PDV-01, PDV-02, CAIXA…).
  2. No sistema (Cloud) → Configurações → Local Gateway, cadastre o endereço: http://<IP>:5080 ou https://<IP>:5443. Salvar.
  3. Os terminais aprendem o endereço sozinhos enquanto online — zero config no terminal.

D. Antes de sair — conferência final

  • Painel abre e mostra Gateway / Storage saudáveis.
  • Serviço com início automático: sc.exe query HorusGateway → RUNNING.
  • Terminais aparecem (pré-autorizados) e ficam online ao simular queda de internet.
  • Endereço cadastrado na Cloud (Configurações → Local Gateway).
  • Eventos pendentes = 0 no painel (nada preso localmente).
  • (HTTPS) .cer instalado em todos os terminais.
Atualização/parada controlada: antes de parar o serviço para atualizar, confira no painel que “Eventos pendentes = 0”. Remover: .\uninstall-service.ps1 (preserva os dados).

Comandos úteis

sc.exe start HorusGateway     # iniciar
sc.exe stop  HorusGateway     # parar
Logs: C:\QuackGateway\publish-service\logs\gateway-AAAA-MM-DD.log

O arquivo .pfx contém a chave privada — mantenha só no Gateway. O .cer é público (pode copiar para os terminais à vontade).
